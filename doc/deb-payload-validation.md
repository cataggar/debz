# Debian payload validation

Use `debz.deb_payload.validate` after acquisition has selected an authenticated repository record. The caller supplies the exact repository, selected and requested package identity, repository filename, byte count, and SHA-256. Validation rejects any disagreement; filenames are diagnostic input and never replace authenticated metadata or the `control` file.

`debz.deb_payload.inspectLocal` provides the separate local-artifact boundary. It derives package, version, and architecture from the validated `control` record instead of requiring repository-selected identity. Optional size, SHA-256, and identity expectations remain fail-closed. The returned provenance labels the result as a local artifact rather than authenticated repository content.

The validator first checks supplied size and SHA-256 expectations, validates the outer `ar` archive, and boundedly decompresses plain, gzip, xz, or zstd `control.tar` and `data.tar` members. Recognized trailing debsigs members (`_gpgorigin`, `_gpgmaint`, and `_gpgarchive`) are structurally bounded and inventoried by `deb_archive`; arbitrary members remain rejected. Structural acceptance is not cryptographic verification. In particular, a key bundled in the same package cannot authenticate that package.

Zstd uses the source-built static libzstd streaming API so valid Debian frames with compressed blocks and content checksums are covered without invoking host tools. `Limits` independently bounds archive/member and signature bytes, compressed and decompressed bytes, decoder window memory, tar entries, aggregate payload bytes, inventory memory, paths, links, control metadata, conffile bytes and entries, and maintainer-script count and bytes. Every failure returns a typed stage/code and outer or inner byte offset. No partially validated result is returned.

The built-in tar policy accepts POSIX USTAR and GNU base headers and verifies checksums, octal metadata and overflow, content padding, two-block termination, and zero-only trailing records. A conventional root directory record is ignored and a single leading `./` is canonicalized. Absolute paths, empty/internal dot components, traversal, control bytes, normalization collisions, duplicate/conflicting destinations, forward hardlinks, escaping links, symlink-mediated descendants, link-ordering attacks, devices, FIFOs, sockets, and unknown special types are rejected. Linux filename backslashes remain literal bytes, including systemd's escaped unit names. Absolute symlink targets are interpreted relative to the archive root for conflict validation, and safe existing symlink chains are supported. Safe USTAR prefix paths and bounded, NUL-terminated GNU long-name/long-link records are supported; PAX records and malformed or dangling GNU extension records remain explicitly unsupported and fail closed.

A successful owned `Validation` inventories canonical control/data entries, compression and byte summaries, maintainer script names/modes/sizes, dependency text, and conffiles (including the Debian `remove-on-upgrade` flag). It never follows host links, touches an install root, executes scripts, or unpacks files. `regularPayloadBytes` and `copyRegularPayloadFiles` expose only explicitly selected, bounded regular-file contents from the already validated data archive.

The optional `repository_descriptor` local profile is deliberately narrow. It allows static source files under `etc/apt/sources.list.d`, keyrings under the standard APT keyring directories, debsig policy/key trees, package-specific documentation, and the package's lintian override. It applies additional entry, per-file, source, keyring, and aggregate-byte bounds. It rejects links, setuid/setgid modes, unrelated payload paths, unsupported control entries, dangerous relationship fields, missing source/keyring content, and conffiles that do not name regular payload files. Maintainer scripts are inventoried and bounded but never executed by this module.

Call `deinit` on successful validation and copied payload-file results.

`debz.deb_payload.fuzzOne` is the side-effect-free entry point for fuzzing decompressor, tar, control, identity, and path/link boundaries. Seed it with the deterministic fixtures under `src/fixtures/deb-payload/` and malformed regressions; always use deliberately small limits for bomb campaigns.
